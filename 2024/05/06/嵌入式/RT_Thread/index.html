    RT_Thread

    RT-Thread 是一个开源的实时操作系统，支持多种 CPU 架构，包括 ARM、MIPS、X86 等。其专为嵌入式场景设计，具有轻量级、高实时性、可裁剪、易移植的特点，非常适合 STM32 系列单片机（如 STM32F103、STM32F407、STM32L4 等）的开发，广泛应用于工业控制、智能硬件、物联网等领域。本文档聚焦 STM32 平台下 RT-Thread 的实操应用，详细讲解工程创建、核心功能使用及常用 API 调用，助力开发者快速上手 RT-Thread 嵌入式开发。

    RT_Thread

    RT-Thread（Real-Time Thread）是由国内团队主导开发的开源实时操作系统（RTOS），相较于其他主流 RTOS（如 FreeRTOS、uC/OS），其不仅具备完整的实时调度内核，还集成了丰富的组件（如文件系统、网络协议栈、GUI 等），且提供了便捷的开发工具（RT-Thread Studio），降低了 STM32 嵌入式开发的门槛。

    在 STM32 平台上，RT-Thread 支持裸机移植、HAL 库移植两种主流方式，适配绝大多数 STM32 系列芯片，可根据项目需求裁剪内核及组件，最小内核仅需几 KB 内存，满足资源受限的 STM32 入门级芯片（如 STM32F103C8T6）的开发需求，同时也能支撑复杂场景下的多线程、多设备协同开发。

    工程创建

    STM32 平台下 RT-Thread 工程创建，推荐使用 RT-Thread Studio 工具（开源免费，集成编译、下载、调试功能），也可通过 Keil MDK 结合 RT-Thread 源码手动创建，以下是两种方式的详细步骤，重点讲解更便捷的 RT-Thread Studio 方式。

    1. RT-Thread Studio 工程创建（推荐）

    1. 安装 RT-Thread Studio：从官网下载对应系统版本（Windows/macOS/Linux），一路下一步完成安装，首次启动会自动安装所需工具链（ARM GCC）。

    2. 新建工程：打开软件，点击「文件」-「新建」-「RT-Thread 项目」，输入项目名称（如 STM32F103_RTThread），选择「基于芯片」，在芯片列表中找到对应型号（如 STM32F103C8T6），选择调试器（如 ST-Link），点击「完成」，软件会自动生成工程模板（包含内核源码、HAL 库、启动文件等）。

    3. 工程配置：右键点击项目，选择「RT-Thread Settings」，可根据需求配置内核（如线程优先级、栈大小）、组件（如是否启用串口控制台、文件系统），配置完成后点击「保存」，软件会自动更新工程文件。

    4. 测试工程：在 main.c 文件中，编写简单的线程代码（如LED闪烁），点击工具栏「编译」-「下载」，调试器连接 STM32 开发板，下载完成后复位开发板，即可看到对应功能实现。

    2. Keil MDK 手动创建工程

    1. 准备文件：下载 RT-Thread 内核源码（从官网获取）、STM32 对应型号的 HAL 库，新建 Keil 工程，选择对应芯片型号，添加启动文件、HAL 库文件、RT-Thread 内核源码（核心文件位于 rtthread/src 目录下）。

    2. 配置工程：在 Keil 中，配置包含路径（添加 RT-Thread 内核、HAL 库的头文件路径），配置宏定义（如 RT_USING_CONSOLE、STM32F103xE 等），设置栈大小（内核栈、线程栈）。

    3. 编写启动代码：在 main.c 中，调用 rtthread_startup() 函数（RT-Thread 内核启动入口），编写线程代码，编译下载即可。

    注意：手动创建工程需手动处理依赖关系，适合有一定 RT-Thread 基础的开发者，新手优先推荐使用 RT-Thread Studio。

    包/组件管理

    RT-Thread 的包/组件管理是其核心优势之一，通过「RT-Thread Package Manager（包管理器）」，可快速集成第三方组件、驱动、算法等，无需手动下载、配置源码，大幅提升开发效率，适配 STM32 平台的常用包/组件如下。

    1. 组件管理（内核自带组件）

    RT-Thread 内核集成了多种基础组件，可通过 RT-Thread Settings 直接启用/禁用，常用组件如下：

    • 串口控制台（RT_USING_CONSOLE）：默认启用，绑定 STM32 的某个串口（如 USART1），可通过串口工具（如 SecureCRT）查看调试信息、输入命令（如 help 查看所有支持的命令），方便开发调试。

    • 内存管理（RT_USING_MEMHEAP/RT_USING_SMALL_MEM）：提供动态内存分配功能（如 rt_malloc()、rt_free()），适配 STM32 的内部 RAM，可根据 RAM 大小选择合适的内存管理算法。

    • 文件系统（RT_USING_FS）：支持 FAT32、SPIFFS 等文件系统，可用于 STM32 外接的 SD 卡、Flash（如 W25Q64），实现文件的读写、创建、删除等操作。

    • 定时器组件（RT_USING_TIMER）：包含软件定时器和硬件定时器的封装，可直接调用 API 实现定时功能，无需手动配置 STM32 的定时器寄存器。

    2. 包管理（第三方扩展包）

    第三方包需通过 RT-Thread Studio 的包管理器下载安装，步骤如下：

    1. 打开 RT-Thread Settings，切换到「包管理器」选项卡，点击「更新包列表」，获取最新的第三方包。

    2. 搜索所需包（如 STM32 驱动包、传感器包），勾选对应包，点击「保存」，软件会自动下载包源码，并添加到工程中，同时配置好依赖关系。

    3. 常用第三方包（适配 STM32）：

      • stm32f1xx-hal：STM32F1 系列 HAL 库驱动包，适配所有 F1 系列芯片。

      • dht11：DHT11 温湿度传感器驱动包，可快速实现传感器数据读取。

      • ssd1306：OLED 显示屏（I2C/SPI 接口）驱动包，支持显示字符、图形。

      • lwip：轻量级 TCP/IP 协议栈包，用于 STM32 网络开发（如以太网、WiFi 模块）。

    注意：安装第三方包后，需根据包的文档，配置对应的硬件引脚（如传感器的 I2C 引脚、串口引脚），确保硬件连接与软件配置一致。

    线程

    线程是 RT-Thread 内核的核心调度单元，STM32 平台下，线程本质上是一段可独立执行的代码，由内核进行实时调度（基于优先级抢占式调度），实现多任务并行执行（宏观并行，微观串行）。相较于裸机开发的「轮询式」，线程开发可避免任务阻塞导致的其他任务无法执行，提升系统实时性。

    1. 线程的核心概念

    • 线程优先级：范围 0~31，0 为最高优先级，31 为最低优先级，内核优先调度优先级高的线程，优先级相同则按时间片轮转调度。

    • 线程栈：每个线程都有独立的栈空间，用于保存线程的上下文（寄存器值、局部变量等），栈大小需根据线程的复杂度配置（一般设置为 256~1024 字节，STM32 内存较小的芯片可适当减小）。

    • 线程状态：包含就绪态、运行态、阻塞态、挂起态、终止态，内核通过状态切换实现线程调度。

    • rt_thread_create()：动态创建线程，返回线程控制块指针。

    • rt_thread_startup()：启动线程，使线程进入就绪态。

    • rt_thread_mdelay(ms)：线程延时（阻塞态），ms 为延时时间，期间释放 CPU 给其他线程。

    • rt_thread_delete(thread)：删除动态创建的线程，释放线程栈空间。

    • rt_thread_suspend(thread)：挂起线程，线程进入挂起态，暂停执行。

    • rt_thread_resume(thread)：恢复挂起的线程，线程进入就绪态。

    注意：STM32 平台下，线程优先级配置需合理，避免高优先级线程长期占用 CPU（如无延时操作），导致低优先级线程无法执行；栈大小需根据线程实际需求配置，过大会浪费 RAM，过小会导致线程栈溢出，程序崩溃。

    IO中断

    STM32 具有丰富的 IO 口，支持外部中断（EXIT）功能，RT-Thread 对 STM32 的 IO 中断进行了封装，无需手动配置中断控制器（NVIC）、中断服务函数，可通过 RT-Thread 提供的 API 快速实现 IO 中断功能，适用于按键触发、传感器电平变化等场景。

    1. IO中断的核心原理

    STM32 的 IO 口可配置为中断模式（上升沿触发、下降沿触发、双边沿触发），当 IO 口电平发生对应变化时，会触发外部中断，中断控制器（NVIC）会暂停当前正在执行的线程，转而执行中断服务函数；中断执行完成后，恢复原来的线程执行。RT-Thread 中，中断服务函数由内核统一管理，开发者只需编写中断回调函数，处理具体的中断逻辑。

    • rt_pin_mode(pin, mode)：配置IO口模式，支持输入、输出、中断等模式（如 PIN_MODE_INPUT_PULLUP、PIN_MODE_OUTPUT）。

    • rt_pin_attach_irq(pin, mode, callback, arg)：绑定中断回调函数，pin 为引脚（通过 GET_PIN(port, pin) 获取），mode 为中断触发模式（上升沿、下降沿等），callback 为中断回调函数。

    • rt_pin_irq_enable(pin, enable)：使能/禁用中断，enable 为 PIN_IRQ_ENABLE（使能）或 PIN_IRQ_DISABLE（禁用）。

    • rt_pin_read(pin)：读取IO口电平（PIN_HIGH 或 PIN_LOW）。

    • rt_pin_write(pin, value)：设置IO口电平（PIN_HIGH 或 PIN_LOW）。

    定时器

    定时器是 STM32 开发中常用的外设，用于实现定时触发、延时、频率测量等功能。RT-Thread 针对 STM32 的定时器，提供了两种封装：软件定时器和硬件定时器，其中软件定时器基于内核时钟实现，无需占用 STM32 的硬件定时器资源；硬件定时器基于 STM32 的定时器外设（如 TIM1、TIM2）实现，定时精度更高，适用于高精度定时场景。

    软件定时器

    软件定时器由 RT-Thread 内核的系统时钟（SysTick）驱动，定时精度取决于系统时钟频率（默认 SysTick 频率为 1ms），支持一次性定时和周期性定时，无需配置 STM32 的硬件定时器，使用便捷，适合对定时精度要求不高的场景（如定时打印、定时检测）。

    1. 软件定时器核心概念

    • 定时周期：从定时器启动到触发回调函数的时间，单位为 ms，最小定时周期为 1ms（与 SysTick 频率一致）。

    • 定时器模式：一次性定时器（触发一次后自动停止）、周期性定时器（每隔固定周期触发一次）。

    • 定时器优先级：软件定时器的回调函数运行在系统线程中，优先级固定（可通过内核配置修改，默认优先级为 20）。

    硬件定时器

    硬件定时器基于 STM32 的定时器外设（如 TIM2~TIM5 为通用定时器，TIM1、TIM8 为高级定时器）实现，定时精度由定时器的时钟频率和分频系数决定，可实现微秒（μs）级定时，适合对定时精度要求高的场景（如 PWM 输出、频率测量、高精度延时）。

    RT-Thread 对 STM32 的硬件定时器进行了封装，通过设备驱动框架（Device Driver）管理，可通过标准 API 操作硬件定时器，无需手动配置定时器的寄存器、分频系数等。

    注意：STM32 的硬件定时器资源有限（如 STM32F103C8T6 有 TIM1~TIM4 四个定时器），使用时需避免资源冲突；定时周期的最小值由定时器的时钟频率决定，可通过修改分频系数调整定时器时钟频率，进而调整定时精度。

    串口中断

    串口是 STM32 与外部设备（如电脑、传感器、蓝牙模块）通信的常用接口，RT-Thread 对 STM32 的串口进行了封装，支持串口中断接收/发送，无需手动配置串口寄存器、中断服务函数，可通过标准 API 实现串口数据的中断接收（避免轮询接收浪费 CPU 资源）和发送，适配大多数串口通信场景。

    1. 串口中断的核心原理

    STM32 的串口支持中断模式，当串口接收到数据（RXNE 标志位置1）或发送完成（TC 标志位置1）时，会触发串口中断，中断控制器会暂停当前线程，转而执行串口中断服务函数；RT-Thread 中，串口中断服务函数由内核统一管理，开发者只需编写串口接收/发送回调函数，处理具体的通信逻辑（如解析接收的数据、触发发送下一包数据）。

    • rt_device_find(dev_name)：查找串口设备（设备名称对应 STM32 的串口，如 uart1 对应 USART1）。

    • rt_device_open(dev, oflag)：打开串口设备，oflag 设为 RT_DEVICE_OFLAG_RDWR | RT_DEVICE_FLAG_INT_RX（中断接收模式），如需中断发送，可添加 RT_DEVICE_FLAG_INT_TX。

    • rt_device_set_rx_indicate(dev, cb)：设置串口接收回调函数，中断接收数据后触发。

    • rt_device_set_tx_complete_indicate(dev, cb)：设置串口发送完成回调函数，中断发送完成后触发。

    • rt_device_read(dev, 0, buf, len)：读取串口接收的数据，buf 为接收缓冲区，len 为读取长度。

    • rt_device_write(dev, 0, buf, len)：发送串口数据，buf 为发送缓冲区，len 为发送长度。

    • rt_device_close(dev)：关闭串口设备，释放资源。

    SPI设备注册

    SPI（Serial Peripheral Interface）是一种高速同步串行通信协议，STM32 支持多个 SPI 外设（如 SPI1、SPI2），常用于与 SPI 接口的设备通信（如 OLED 显示屏、Flash 芯片、ADC 芯片等）。RT-Thread 提供了 SPI 设备驱动框架，开发者只需注册 SPI 设备、配置 SPI 通信参数，即可通过标准 API 实现与外部 SPI 设备的通信，无需手动配置 SPI 寄存器。

    1. SPI设备注册的核心步骤

    STM32 平台下，RT-Thread 中 SPI 设备注册分为两步：① 初始化 SPI 外设（配置引脚、通信参数）；② 向 RT-Thread 内核注册 SPI 设备，使其成为系统可识别的设备，后续可通过设备句柄操作 SPI 设备。

    常用的 SPI 通信参数：波特率、时钟极性（CPOL）、时钟相位（CPHA）、数据位数、主从模式（STM32 通常作为 SPI 主机）。

    • rt_device_find(dev_name)：查找 SPI 设备（设备名称对应 STM32 的 SPI 外设，如 spi1 对应 SPI1）。

    • rt_spi_configure(dev, cfg)：配置 SPI 通信参数，cfg 为 SPI 配置结构体（模式、数据位数、波特率等）。

    • rt_device_open(dev, oflag)：打开 SPI 设备，oflag 设为 RT_DEVICE_OFLAG_RDWR。

    • rt_spi_transfer(dev, send_buf, recv_buf, len)：SPI 同步收发数据，send_buf 为发送缓冲区，recv_buf 为接收缓冲区，len 为数据长度。

    • rt_spi_send(dev, send_buf, len)：SPI 仅发送数据。

    • rt_spi_recv(dev, recv_buf, len)：SPI 仅接收数据。

    • rt_device_close(dev)：关闭 SPI 设备，释放资源。

    常用API

    本章节汇总 STM32 平台下 RT-Thread 开发中最常用的 API，按功能分类，方便开发者快速查询、调用，涵盖线程、IO、定时器、串口、SPI 等核心功能，每个 API 包含功能说明、参数说明及简单使用示例。

    1. 系统核心 API

    • rt_thread_startup()：启动线程，使线程从就绪态进入运行态。

    参数：thread - 线程控制块指针（由 rt_thread_create() 返回）。

    示例：rt_thread_startup(led_thread);

    • rt_kprintf(const char *fmt, …)：串口打印函数（需启用串口控制台），用法与 printf 一致。

    示例：rt_kprintf(“Hello RT-Thread!\r\n”);

    • rt_thread_mdelay(rt_int32_t ms)：线程延时，单位 ms，期间释放 CPU。

    示例：rt_thread_mdelay(500); // 延时500ms

    • rt_memset(void *ptr, rt_int32_t value, rt_size_t size)：内存初始化，将 ptr 指向的内存块（大小 size）填充为 value。
      示例：rt_memset(uart_rx_buf, 0, sizeof(uart_rx_buf)); // 清空接收缓冲区

    2. 线程相关 API

    • rt_thread_create(const char *name, void (*entry)(void *parameter), void *parameter, rt_uint32_t stack_size, rt_uint8_t priority, rt_uint32_t tick)：动态创建线程。
      参数：name - 线程名称；entry - 线程入口函数；parameter - 线程参数；stack_size - 栈大小（字节）；priority - 线程优先级（0~31）；tick - 时间片大小。

    示例：led_thread = rt_thread_create(“led_thread”, led_thread_entry, RT_NULL, 512, 10, 10);

    • rt_thread_delete(rt_thread_t thread)：删除动态创建的线程。

    示例：rt_thread_delete(led_thread);

    • rt_thread_suspend(rt_thread_t thread)：挂起线程。

    示例：rt_thread_suspend(uart_thread);

    • rt_thread_resume(rt_thread_t thread)：恢复挂起的线程。

    示例：rt_thread_resume(uart_thread);

    3. IO 与中断相关 API

    • rt_pin_mode(rt_base_t pin, rt_uint8_t mode)：配置 IO 口模式。

    参数：pin - 引脚（GET_PIN(port, pin) 获取，如 GET_PIN(A, 0)）；mode - 模式（PIN_MODE_INPUT、PIN_MODE_OUTPUT 等）。

    示例：rt_pin_mode(GET_PIN(A, 0), PIN_MODE_OUTPUT);

    • rt_pin_write(rt_base_t pin, rt_uint8_t value)：设置 IO 口电平。

    参数：value - PIN_HIGH（高电平）或 PIN_LOW（低电平）。

    示例：rt_pin_write(GET_PIN(A, 0), PIN_HIGH);

    • rt_pin_attach_irq(rt_base_t pin, rt_uint8_t mode, void (*hdr)(void *args), void *args)：绑定 IO 中断回调函数。

    参数：mode - 中断触发模式（PIN_IRQ_MODE_FALLING 等）；hdr - 中断回调函数。

    示例：rt_pin_attach_irq(GET_PIN(A, 1), PIN_IRQ_MODE_FALLING, irq_callback, RT_NULL);

    • rt_pin_irq_enable(rt_base_t pin, rt_uint8_t enable)：使能/禁用 IO 中断。

    示例：rt_pin_irq_enable(GET_PIN(A, 1), PIN_IRQ_ENABLE);

    4. 定时器相关 API

    • rt_timer_create(const char *name, void (*timeout)(void *parameter), void *parameter, rt_uint32_t time, rt_uint8_t flag)：创建软件定时器。
      参数：time - 定时周期（ms）；flag - 定时器模式（RT_TIMER_FLAG_ONE_SHOT 一次性、RT_TIMER_FLAG_PERIODIC 周期性）。

    示例：period_timer = rt_timer_create(“period_timer”, period_timer_cb, RT_NULL, 1000, RT_TIMER_FLAG_PERIODIC);

    • rt_timer_start(rt_timer_t timer)：启动软件定时器。

    示例：rt_timer_start(period_timer);

    • rt_device_write(rt_device_t dev, rt_off_t pos, const void *buffer, rt_size_t size)：设置硬件定时器周期（size 为周期，单位 ns）。

    示例：rt_device_write(timer_dev, 0, NULL, 100000); // 100μs周期

    5. 串口相关 API

    • rt_device_find(const char *name)：查找串口/定时器/SPI 设备。

    示例：uart_dev = rt_device_find(“uart1”);

    • rt_device_open(rt_device_t dev, rt_uint8_t oflag)：打开设备。

    示例：rt_device_open(uart_dev, RT_DEVICE_OFLAG_RDWR | RT_DEVICE_FLAG_INT_RX);

    • rt_device_read(rt_device_t dev, rt_off_t pos, void *buffer, rt_size_t size)：读取设备数据（串口接收）。

    示例：rt_device_read(uart_dev, 0, uart_rx_buf, 32);

    • rt_device_write(rt_device_t dev, rt_off_t pos, const void *buffer, rt_size_t size)：写入设备数据（串口发送）。

    示例：rt_device_write(uart_dev, 0, “Test”, 4);

    6. SPI 相关 API

    • rt_spi_configure(rt_device_t dev, struct rt_spi_configuration *cfg)：配置 SPI 通信参数。

    示例：rt_spi_configure(spi_dev, &spi_cfg);

    • rt_spi_transfer(rt_device_t dev, const void *send_buf, void *recv_buf, rt_size_t length)：SPI 同步收发数据。

    示例：rt_spi_transfer(spi_dev, send_buf, recv_buf, 4);

    其它

    1. 常见问题排查

    • 线程无法启动：检查线程创建是否成功（判断线程控制块是否为 NULL）；检查线程优先级是否合理，避免被高优先级线程阻塞；检查线程栈大小是否足够。

    • 串口无法打印：检查串口设备是否查找、打开成功；检查串口引脚配置是否正确（如 USART1 对应 PA9-TX、PA10-RX）；检查波特率、数据位、停止位是否与串口工具一致。

    • 中断无法触发：检查 IO 口模式是否配置为中断模式；检查中断触发模式是否与硬件连接一致（如按键中断是否为下降沿触发）；检查中断是否已使能；检查中断回调函数是否绑定正确。

    • SPI 通信失败：检查 SPI 设备是否注册、配置成功；检查片选引脚是否正确操作（选中/取消选中）；检查 SPI 通信参数（模式、波特率）是否与外部设备一致；检查硬件接线是否正确（SCLK、MOSI、MISO 引脚对应）。

    • 定时器定时不准：软件定时器检查系统时钟（SysTick）是否准确；硬件定时器检查定时器时钟频率、分频系数配置是否正确；避免在定时器回调函数中执行耗时操作。

    2. 开发注意事项

    • 资源分配：STM32 的 RAM、Flash 资源有限，线程栈大小、缓冲区大小需合理配置，避免浪费资源；优先使用动态分配函数（如 rt_malloc()），避免静态分配占用过多 RAM。

    • 优先级配置：线程优先级遵循“高优先级任务优先执行”原则，避免高优先级线程长期占用 CPU（需添加延时操作），确保低优先级线程有执行机会；中断优先级需高于所有线程优先级，确保中断能及时响应。

    • 代码规范：编写代码时，注意命名规范（如线程名称、设备名称统一前缀），添加注释，便于后期维护；
