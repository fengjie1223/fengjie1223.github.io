    Modbus 协议完整文档

    一、Modbus 协议概述

    Modbus 是由施耐德公司于1979年推出的工业现场串行通信协议，是工业自动化领域应用最广泛的开放式、标准化通信协议之一，主打简单易用、跨厂商兼容、轻量高效的特点。

    • 核心定位：为工业设备（PLC、变频器、传感器、仪表等）提供统一的通信交互标准，实现不同厂商、不同类型设备之间的互联互通。

    • 通信架构：基于主从式（Client/Server） 通信模型，由主站（Client）主动发起请求，从站（Slave/Server）被动响应，无主站请求时从站不主动发送数据。

    • 协议优势：无专利限制、协议解析简单、硬件要求低，支持串行和以太网多种传输方式，适配工业现场复杂的通信环境。

    • 应用场景：工业自动化产线数据采集、设备远程控制、楼宇自控、智能家居、电力监控等场景，是工业物联网（IIoT）底层通信的核心协议之一。

    二、Modbus 核心通信模型

    Modbus 协议全程遵循主从式（Client/Slave） 通信模型，这是所有Modbus衍生版本的基础通信规则，无主站请求时，从站始终处于静默监听状态，具体分工如下：

    1. 主站（Client/Master）

    • 唯一发起通信的主体，同一通信链路中仅允许存在一个主站（RTU/ASCII），TCP版本支持多主站并发。

    • 核心职责：主动向指定从站发送请求指令、等待从站响应、校验响应数据合法性、解析并处理数据（如采集传感器值、下发设备控制指令），对无响应/异常响应的从站做超时、重发等处理。

    2. 从站（Slave/Server）

    • 被动响应方，同一通信链路中可挂载多个从站（RTU/ASCII通常支持32/64个，TCP无节点数限制）。

    • 核心职责：实时监听总线/网络请求，仅解析指向自身唯一标识（RTU为地址，TCP为IP）的请求帧；校验请求合法性后执行对应操作（读/写寄存器、返回设备状态）；按协议格式封装响应数据并回传，对非法请求返回异常响应帧。

    三、Modbus 常用传输模式

    Modbus 协议根据传输介质和编码方式，衍生出3种核心传输模式，其中 Modbus RTU 和 Modbus TCP 为工业现场最主流的版本，Modbus ASCII 因传输效率低仅用于部分老旧设备。

    1. Modbus RTU

    基于串行总线（RS-232/RS-485） 的二进制传输模式，是工业现场最常用的版本，主打传输效率高、抗干扰能力强，适配现场总线的短距离、多节点通信场景。

    （1）Client（主站）

    • 通信特性：基于RS-232/RS-485传输，二进制编码（数据帧无冗余），通信速率支持2400~19200bps，主从站必须统一波特率、数据位（8位）、停止位（1/2位）、校验位（奇/偶/无） 等串行参数，否则无法通信。

    • 核心功能：主动发送功能码指令，指定目标从站地址（1~247），携带寄存器地址、数据长度/写入值等参数；接收从站响应帧，通过CRC16循环冗余校验验证数据完整性；解析有效数据并完成业务逻辑（如采集温湿度、控制电机启停）。

    • 帧格式（固定结构，字节数随数据段变化）：从站地址(1字节) + 功能码(1字节) + 数据段(N字节) + CRC16校验(2字节)

    • 关键要求：发送请求后需设置合理超时时间（通常100~500ms），避免总线阻塞；支持总线故障检测，对校验错误、无响应的从站执行重发或异常标记。

    （2）Slave（从站）

    • 通信特性：与主站保持完全一致的串行通信参数，实时监听总线数据，仅解析地址匹配的帧数据，忽略其他从站地址的请求，降低资源占用。

    • 核心功能：接收主站请求帧，校验从站地址和功能码合法性；执行对应操作（读取本地寄存器数据、写入指定寄存器值、返回设备异常状态）；按RTU格式封装响应数据，在规定时间内回传主站；若请求非法（功能码不支持、寄存器地址越界），返回异常响应帧（功能码最高位置1 + 异常码）。

    • 关键要求：本地需维护Modbus寄存器映射表，确保物理量（如传感器数据、设备开关状态）与寄存器地址一一对应；响应延迟需控制在总线允许范围内，避免主站超时；总线内从站地址必须唯一，禁止地址冲突。

    2. Modbus TCP

    基于以太网TCP/IP协议的传输模式，是Modbus协议的以太网扩展版本，解决了串行Modbus的传输距离短、节点数有限、不支持多主站等问题，适配工业局域网/广域网的远距离、多设备并发通信场景。

    （1）Client（主站）

    • 通信特性：基于以太网（TCP/IP v4/v6）传输，采用MBAP（Modbus Application Protocol）报文头封装，兼容局域网/广域网；传输速率由以太网带宽决定（10/100/1000Mbps），无串行通信的参数匹配限制；使用TCP 502端口（Modbus标准端口，不可随意修改）。

    • 核心功能：向从站IP地址发起TCP连接，支持单连接/多连接（同时与多个从站通信）；发送Modbus TCP请求帧，包含7字节MBAP报文头 + 传统Modbus RTU应用数据；通过MBAP中的事务标识匹配请求与响应（解决多请求并发乱序问题）；解析响应数据并处理通信异常（断连、超时、网络丢包）。

    • 帧格式：MBAP报文头(7字节) + RTU应用数据(N字节)

      • MBAP报文头详解：事务标识(2字节，请求/响应一一对应) + 协议标识(2字节，固定0x0000表示Modbus) + 长度(2字节，后续应用数据的总字节数) + 单元标识(1字节，映射串口从站地址，纯TCP场景设为0)

    • 关键要求：确保主从站网络连通性，支持TCP自动重连机制；MBAP的长度字段需准确标识后续应用数据字节数，否则从站解析失败；防火墙需开放502端口，避免网络阻塞。

    （2）Slave（从站）

    • 通信特性：基于以太网TCP/IP协议，监听本地TCP 502端口，等待客户端连接；支持多客户端并发通信（无主站数量限制），通过IP地址唯一标识，无地址冲突问题；传输距离无限制（只要网络可达）。

    • 核心功能：监听TCP 502端口，接受客户端连接并维护连接会话；解析请求帧的MBAP报文头和功能码，校验合法性后操作本地寄存器映射表；封装响应帧（MBAP报文头 + 响应应用数据），通过TCP连接回传客户端；对非法请求返回含异常码的响应帧，同时记录通信日志（连接状态、请求错误类型）。

    • 关键要求：配置固定IP地址和子网掩码，确保网络可达；本地寄存器映射表需与客户端请求的寄存器类型、地址严格匹配；具备并发处理能力，避免多客户端请求时的响应阻塞；支持TCP异常断连检测，及时释放无效连接资源。

    3. Modbus ASCII（补充）

    基于串行总线的ASCII字符编码传输模式，是早期Modbus的基础版本，主打调试方便、易识别，但传输效率低（数据帧冗余大），目前仅用于部分老旧设备或调试场景。

    • 核心特性：所有数据以ASCII字符（09、AF）传输，帧起始符为:，结束符为\r\n；采用LRC（纵向冗余校验），校验能力弱于CRC16；通信速率仅支持300~9600bps。

    • 应用场景：仅用于设备调试、串口监控等对传输效率要求低的场景，工业现场已基本被Modbus RTU替代。

    四、Modbus 四大核心寄存器类型

    Modbus 协议通过寄存器实现工业设备的参数读写，将设备的物理量（输入、输出、状态、参数）映射为四种标准化寄存器，所有主从站的交互均围绕这四种寄存器展开，寄存器地址为16位，地址范围0~65535，不同寄存器的读写属性、用途不同，是Modbus协议的核心数据载体。

    寄存器类型 英文名称 读写属性 核心用途 典型地址范围 对应常用功能码
    离散输入寄存器 Discrete Inputs 只读 采集设备数字量输入（如按钮、限位开关状态） 00001~09999 02（读）
    线圈寄存器 Coils 读写 控制设备数字量输出（如继电器、指示灯） 00001~09999 01（读）、05（单写）、15（多写）
    输入寄存器 Input Registers 只读 采集设备模拟量输入（如传感器、仪表检测值） 30001~39999 04（读）
    保持寄存器 Holding Registers 读写 存储/修改设备参数、模拟量输出（如变频器频率、PLC设定值） 40001~49999 03（读）、06（单写）、16（多写）

    寄存器关键说明

    1. 地址表示：Modbus协议有1-based（基于1） 和0-based（基于0） 两种地址表示方式，工业现场常用1-based，编程时需注意转换（如1-based地址40001对应0-based地址0000）；

    2. 数据长度：所有寄存器均为16位（2字节），若需存储32位数据（如浮点数、大整数），需连续占用2个寄存器，主从站需约定高低字节顺序；

    3. 映射关系：从站需将本地物理量与寄存器地址一一映射（如将温度传感器值映射到保持寄存器40001），主站通过读写对应地址实现数据交互。

    五、Modbus 常用功能码

    功能码是Modbus请求帧的核心指令，为1字节（0~255），用于指定从站需执行的操作类型（读/写寄存器、返回异常等），主站通过发送功能码告知从站“要做什么”，从站根据功能码执行对应操作并返回响应。

    Modbus 功能码分为正常功能码（01~127） 和异常功能码（128~255），异常功能码由正常功能码最高位置1得到（如功能码03异常为131=03+128），用于告知主站请求失败的原因。

    工业现场最常用的标准功能码（必实现）

    功能码 名称 操作类型 对应寄存器类型 核心作用
    01 读线圈状态 读 线圈寄存器 批量读取多个数字量输出状态（如指示灯、继电器）
    02 读离散输入状态 读 离散输入寄存器 批量读取多个数字量输入状态（如按钮、限位开关）
    03 读保持寄存器 读 保持寄存器 批量读取多个保持寄存器数据（如设备参数、模拟量）
    04 读输入寄存器 读 输入寄存器 批量读取多个输入寄存器数据（如传感器、仪表值）
    05 写单个线圈 写 线圈寄存器 单独控制一个数字量输出（如单独点亮一个指示灯）
    06 写单个保持寄存器 写 保持寄存器 单独修改一个设备参数（如设置变频器频率）
    15（0F） 写多个线圈 写 线圈寄存器 批量控制多个数字量输出（如同时控制多个继电器）
    16（10） 写多个保持寄存器 写 保持寄存器 批量修改多个设备参数（如同时设置多个PLC参数）

    异常功能码与常见异常码（核心）

    当从站接收到非法请求时，返回异常功能码（原功能码+128） + 1字节异常码，主站通过异常码判断请求失败原因，常见异常码如下：

    异常码 异常名称 产生原因
    01 非法功能码 主站发送的功能码从站不支持/未实现
    02 非法数据地址 主站请求的寄存器地址超出从站有效地址范围
    03 非法数据值 主站写入的数据超出从站寄存器的有效值范围
    04 从站设备故障 从站执行请求时发生硬件/软件故障（如寄存器读写失败）
    05 确认 从站已接收请求并开始执行，需等待完成（极少用）
    06 从站设备忙 从站正在执行其他操作，暂时无法响应

    六、Modbus 协议关键通信参数

    1. Modbus RTU 串行通信参数（必须主从一致）

    Modbus RTU基于RS-232/RS-485串行总线，所有挂在同一总线的主从站必须配置完全相同的串行参数，否则会出现数据解析失败、通信中断，核心参数如下：

    • 波特率：2400/4800/9600/19200bps（工业现场最常用9600bps）；

    • 数据位：固定8位（Modbus协议规定，不可修改）；

    • 停止位：1位或2位（通常1位，与波特率匹配）；

    • 校验位：奇校验（Odd）/偶校验（Even）/无校验（None）（通常无校验，需配合1位停止位）；

    • 流控：无（RS-485为半双工通信，无需硬件流控）。

    2. Modbus TCP 网络通信参数

    Modbus TCP基于以太网TCP/IP，无串行参数限制，核心配置为网络参数，确保主从站网络可达即可：

    • 标准端口：TCP 502（Modbus协议规定，主从站均需遵循，防火墙需开放）；

    • 从站配置：固定IP地址、子网掩码、网关（确保主站能通过IP访问）；

    • 传输协议：TCP（面向连接，保证数据可靠传输，禁止使用UDP）；

    • MTU值：默认以太网1500字节，无需修改（避免数据分片）。

    七、Modbus 协议异常处理与常见问题

    1. 核心异常处理机制

    • 数据校验：RTU采用CRC16校验，ASCII采用LRC校验，TCP基于TCP/IP本身的校验机制，从站校验失败则直接丢弃帧，不返回响应；

    • 异常响应：从站解析请求后，若发现非法操作（如非法功能码、地址越界），立即返回异常响应帧，主站根据异常码做对应处理；

    • 超时重发：主站发送请求后，若在规定超时时间内未收到从站响应，判定为通信超时，可执行1~3次重发，超过次数则标记设备离线。

    2. 工业现场常见通信问题及解决方法

    常见问题 核心原因 解决方法
    总线无响应（RTU） 主从站串行参数不一致/从站地址冲突/总线短路 统一波特率/校验位等参数；检查从站地址是否唯一；用万用表检测RS-485总线A/B线是否短路
    数据解析错误（RTU） CRC16校验失败/总线干扰大/接线接触不良 检查接线是否牢固；在总线两端增加120Ω终端电阻；远离强电干扰源（如变频器、电机）
    网络无法连接（TCP） 从站IP错误/502端口被屏蔽/网络不通 核对从站固定IP；关闭防火墙或开放502端口；用ping命令测试主从站网络连通性
    部分寄存器读写失败 寄存器地址/类型不匹配/从站寄存器只读 核对从站寄存器映射表，确认地址和读写属性；避免向只读寄存器（如输入寄存器）写入数据
    多客户端并发响应慢（TCP） 从站硬件性能低/并发连接数过多 更换高性能从站设备；限制客户端最大连接数；优化请求频率

    八、Modbus 协议的工业应用拓展

    1. Modbus TCP/IP 转 RTU/ASCII 网关：解决串行Modbus设备的以太网接入问题，网关作为Modbus TCP从站与以太网主站通信，同时作为Modbus RTU主站与现场串行从站通信，实现“串行设备上云/上局域网”；

    2. Modbus 与工业物联网（IIoT）：通过边缘网关采集Modbus设备数据，转换为MQTT/HTTP等物联网协议，上传到云平台（如阿里云、华为云），实现工业设备的远程监控、数据分析、故障预警；

    3. 跨协议兼容：多数工业PLC、SCADA系统（如WinCC、Intouch、组态王）均原生支持Modbus协议，可直接与Modbus设备通信，无需额外开发驱动；

    4. 安全加固：Modbus协议本身无加密和身份认证机制，工业现场可通过网络隔离（如工业防火墙）、VPN加密、端口映射等方式提升通信安全性，避免非法设备接入。

    九、Modbus 协议核心特点总结

    1. 开放性：无专利限制，所有厂商均可免费实现，跨厂商兼容能力强；

    2. 轻量性：协议帧结构简单，解析难度低，硬件要求不高，适配低成本工业设备；

    3. 灵活性：支持串行（RTU/ASCII）和以太网（TCP）多种传输方式，适配不同工业通信场景；

    4. 扩展性：通过功能码和寄存器实现灵活的读写操作，支持多节点、多设备并发通信（TCP）；

    5. 局限性：无原生加密机制，通信安全性较低；RTU版本受串行总线限制，传输距离和节点数有限。
